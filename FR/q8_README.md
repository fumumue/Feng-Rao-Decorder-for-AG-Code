# uh_newton.c:ニュートン多角形で基底を作るフェンラオ(多数決)復号器

`uh.c` の一点符号の基底構成を、局所展開(Laurent 展開)からニュートン多角形に置き換えたものです。

## 1. ニュートン多角形を使っているプログラムはあるか

| 種類 | ファイル | 備考 |
|---|---|---|
| すでに使っている(ECP型) | `aha.c`、`bbgs_toric.c`、`multi.c`、`vx.c` | BBGS 曲線専用(係数固定) |
| すでに使っている(フェンラオ多数決型) | `fr71.c` | BBGS 曲線専用 |
| 使っていない(局所展開で基底を作る) | `uh.c`、`over.c`、`bbsg_decode.c` | 一般の曲線向けだが基底の計算が遅い |
| 部品のみ | `mkbase2.h` | 呼び出し元が未アップロードのため単独では使えない |

## 2. 直す対象に `uh.c` を選んだ理由

- 一般の曲線に対して FR・BMS・VOTE(多数決)を持つ。
- `uh.c`、`over.c`、`bbsg_decode.c` は同系統の版違いで、`uh.c` が一番新しく上限(`MAXGENUS`)が大きい。
- `mkbase2.h` が前提とする `curve`、`EvalBasis`、`build_basis_from_list` などは、アップロードされたどのファイルにも無かった。そのため考え方だけを取り入れ、`uh.c` の構造(基底 = 極の位数 `rho` と評価ベクトル)に合わせて新しく書いた。

## 3. 変更内容

### 3.1 基底の作り方

辺 e が格子長1(単一の場所)のとき、単項式 x^i y^j は次を満たせば L(MP) に入ります。

- 他の辺 k について `w_k · (i,j) >= 0`(その場所で極を持たない)
- `-w_e · (i,j) <= M`(極の位数が M 以下)

極の位数は `-w_e · (i,j)` です。同じ重みの単項式は極の位数の低い項しか違わないので、重みごとに代表を1つ選びます。

### 3.2 実行時の認証

得られた重みの種類数が Riemann-Roch の次元 `M+1-g` と一致するかを毎回確認します。

- 一致すれば完全な基底。
- 一致しなければ、旧方式(Laurent 展開)に自動で切り替える。

### 3.3 極の候補の追加

格子長1の辺の場所を極の候補に加えました(原点側の辺 `E0` を含む)。

BBGS (q=4) の無限遠の有理点は辺 `E2`(格子長3)上に3つあり、単項式では区別できません。旧方式では Laurent 展開が必要だった場所です。原点の辺 `E0` は格子長1なので、単項式だけで基底が作れます。

### 3.4 Laurent 単項式を使うときの注意

負の指数が出る場合は、x=0 または y=0 の点を符号位置から外します。ただし、軸上の点が原点だけであること(`F(0,y)` と `F(x,0)` が単項式)を確認し、満たさなければ旧方式に切り替えます。BBGS (q=4) では原点1点だけが除かれます(n = 1009 → 1008)。

## 4. 結果(GF(64)、q=4 の BBGS 曲線、g=123)

### 4.1 速度(VOTE のみ)

| 誤り数 | | 旧版 | 新版 |
|---|---|---|---|
| 100 | 全体 | 6.4 s | 0.33 s |
| 250 | 基底構成を含む準備 | 15.9 s | 0.00 s |
| 250 | 全体 | 17.4 s | 0.65 s |

誤り100個・250個のいずれも、旧版・新版とも全員正しく復元できました。

### 4.2 設計距離

新しい極(`E0`)の方が設計距離が大きくなりました。

| 設定 | 旧版の極(`E2` 上) | 新版の極(`E0`) |
|---|---|---|
| M=286 のときの d_FR | 45(訂正 22 個) | 54(訂正 26 個) |

26個の誤りを VOTE で3回復号し、3/3 成功しました。

### 4.3 FR・BMS・VOTE の3方式

M=410、誤り20個、5回で、新方式・旧方式(`-nonewton`)とも FR 5/5、BMS 5/5、VOTE 5/5 でした。

### 4.4 他の曲線

- q=2(GF(2^5)):VOTE 5/5(3個の誤り)
- エルミート曲線(`y^4+y=x^5`、GF(2^4)):VOTE 5/5(4個の誤り)

## 5. 使い方

```sh
cc -O2 -fopenmp -std=gnu11 -o uh_newton uh_newton.c   # -fopenmp は省略可
./uh_newton --m 6 --errors 250 -vote
./uh_newton --m 6 --errors 20 --M 410 -n 5            # FR・BMS・VOTE を5回
```

追加したオプションは次の2つです。

| オプション | 内容 |
|---|---|
| `-nonewton` | 旧方式(Laurent 展開)で基底を作る(比較用) |
| `-allplaces` | 旧方式の極も評価して、d_FR が最良のものを選ぶ(遅い) |

既定では、ニュートン多角形で基底が認証された極があれば旧方式の極は評価しません。

## 6. 制限と今後

- 多点符号(`--pole`)は従来どおりで、ニュートン多角形版にはしていません。
- 元から `MAXB=1400` の制限があり、種数が大きい曲線(q=8 は g=2037)は動きません。制限値を上げれば広げられます。
- 格子長1の辺が無い曲線では、旧方式に切り替わります(速度は旧版と同じ)。
- `ag_decoder.c` 系(鈴木曲線)や `over.c`、`bbsg_decode.c` にも、同じ手順で移せます。

## 7. 追加の変更(スキップ廃止・上限表示・誤り256個)

### 7.1 FR/BMS をスキップしない
- 誤り数が基本アルゴリズムの保証範囲(τ)を超えていても、FR と BMS を実行して結果(OK/FAILED)を表示する。
- 従来のスキップ動作が必要なときは `-strict` を付ける。

### 7.2 既定の M を自動で決める
- `--M` を省略したとき、FR/BMS と多数決のすべてが `--errors` 個を訂正できる最小の M(`2t+3g-1`)を使う。
- その M が曲線の点数などに収まらない場合は、多数決の最小値(`2t+2g`)にして、FR/BMS は保証範囲外で実行する旨を表示する。

### 7.3 動くパラメータの上限を表示する
- 実行の最初に上限を表示する。`-limits` を付けると表示だけして終了する。
- 表示する内容:
  - 種数 g と点数 n
  - 使える M の範囲
  - その M で訂正できる誤りの最大数(FR/BMS と多数決)
  - 指定した誤り数に必要な M
- パラメータが範囲外で失敗するときも、同じ表を出力する。

```sh
./uh_newton --m 6 -limits
```

### 7.4 誤り256個の確認(GF(64)、q=4、g=123)
| 方式 | 結果 |
|---|---|
| FR | 8/8 成功 |
| BMS | 8/8 成功 |
| VOTE | 8/8 成功 |

- 既定の M は 880。1回の実行は約1秒。
- この設定の上限は FR/BMS が258個、多数決が319個。
- 300個では多数決のみ成功し、FR/BMS は保証範囲外で失敗した(想定どおり)。

### 7.5 動かない設定
- 次の設定は、ビルドの上限(`MAXB=1400`)や点数が足りず動かない。
  - `--m 9`(q=8、g=2037)
  - `--m 7`(n=128)
- 現在のコードでは、表示で理由を確認できる。
- g=2037 を扱うには、`MAXB` などを大きくする改造が別途必要になる。

## 8. q=8(GF(2^9)、g=2037)で誤り256個

- 符号長は既定で 8192 に制限した(`--len L` で変更可)。1点(原点)は Laurent 単項式のため除かれ、実際は n=8191。
- 配列の上限 `MAXB` を 1400 から 7000 に拡大し、上限チェックを実際の基底数 `M+1` 基準に直した。
- 多数決の内側の計算を、対数表による分岐なしの積和と結果の再利用で高速化した。
- 実行例:

```sh
./uh_newton --m 9 --q 8 --errors 256 -vote
```

| 項目 | 値 |
|---|---|
| M | 4586(多数決の最小値) |
| 基底の構成 | 0.13 s |
| 双対基底の構成 | 約39 s |
| 多数決(BMS+投票) | 約132 s |
| 結果 | 256/256 復号成功(誤った投票 0、同数 0) |

- この長さでは FR/BMS の基本限界(M ≥ 6622)に届かない(M ≤ 6153)ため、`-vote` を付けて多数決のみ実行する。
- 1コア・約4GBの環境で、乱数 seed=1 の1回のみ確認した。
