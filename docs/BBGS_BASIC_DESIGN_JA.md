# BBGS曲線版ベーシックアルゴリズム：設計・実装ノート

## このブランチの目的

このブランチでは、既存のFeng–Rao系AG符号コードを参考に、Bassa–Beelen–Garcia–Stichtenoth（BBGS）塔の関数体から評価型AG符号を構成し、規定を計算し、ベーシック復号へ接続することを目標とする。

**現段階では、BBGS曲線の特定レベル・有限体・有理点集合が確定していないため、数値パラメータや復号成功を実装済みとは扱わない。** 以前の会話に出た GF(32), n=496, g=75 も未検証値であり、このノートでは採用しない。

## 1. 入力として確定させる情報

BBGSは単一の平面曲線名ではなく、有限体と塔の段数などで具体的な関数体が決まる塔である。実装の入力は少なくとも次の情報を持つ必要がある。

- 基礎有限体とその既約多項式（または有限体の明示的な表現）
- BBGS塔の定義・再帰式と段数
- 使用する有理点の表現
- 評価から除外する場所（特に極の場所）
- 1点評価なら指定する有理場所 Q と評価 divisor D

再帰式の流儀や添字の取り方を固定せずに、特定の「E2」などの呼称だけから曲線を決め打ちしない。

## 2. 符号の構成

滑らか・射影・幾何学的既約な曲線 X/F_q、相異なる有理点 P_1,...,P_n、およびそれらと交わらない divisor G を取り、

```
D = P_1 + ... + P_n
C_L(D,G) = { (f(P_1),...,f(P_n)) : f in L(G) }
```

を構成する。

1点型では G = mQ とする。deg(G) < n なら評価写像の核が自明であり、符号長は n。さらに deg(G) > 2g-2 なら Riemann–Roch の定理から

```
dim L(G) = deg(G) + 1 - g
```

となる。一般の評価型AG符号に対する距離の保証は

```
d >= n - deg(G)
```

である。1点型 G=mQ, deg(Q)=1 なら k=m+1-g（m>2g-2）および d>=n-m。

これらは設計下界であり、真の最小距離を計算した結果ではない。プログラムは両者を別々に表示する。

## 3. RR空間の基底

BBGS塔の関数体について、指定した場所 Q における各関数の付値を計算する。候補関数を単に総次数で並べるのではなく、塔の関係式で簡約し、極の次数が m 以下の関数から一次独立な基底を得る。

実装では次を検査する。

1. 各基底候補が Q 以外に極を持たないこと。
2. Q での極次数が m 以下であること。
3. 関数体の関係式で同値な候補を重複計上しないこと。
4. 基底の個数が RR の理論次元と一致すること（m>2g-2 の場合）。
5. 評価行列の階数が基底数と一致すること（deg(G)<n の場合）。

## 4. ベーシック復号への接続

まず評価行列と双対側のシンドロームを有限体上で計算できるようにする。その後、BBGS塔に対応する場所の半群・重み順序と syndrome の関係を実装し、Feng–Rao型の基本復号手順へ接続する。

復号器は次の段階に分ける。

- 有理点と関数の評価：シンドローム計算の検証
- 半群・重み列の生成：復号に用いる順序の検証
- 誤り位置候補の決定：理論上の訂正範囲を明示
- 誤り値の線形方程式による決定
- 訂正後の符号語検査と失敗判定

訂正能力を超える入力について誤った符号語を返さず、復号失敗を明示する。最初のテストでは、誤り数を設計訂正範囲以下に制限したランダム誤りと、境界・範囲外のテストを分ける。

## 5. CLIと出力予定

実装時のコマンドライン引数は、有限体、塔の段数、評価点の選択、m、および誤り数を指定できる設計とする。結果には次を出力する。

- 有限体と塔の識別情報
- 有理点数と採用評価点数 n
- 種数 g（理論値または検証済み計算値）
- RR基底とその個数
- 評価行列の階数
- [n,k,d下界] と符号化率
- 設計訂正範囲
- 復号テストの成功・失敗件数

## 6. 現在の実装状況

この文書は実装仕様と数学的な検査条件をまとめた初期ノートである。現時点ではBBGS固有の関数体演算、RR基底生成、BBGS用ベーシック復号器は未実装であり、数値実験結果も未取得である。既存の `mp.c` は変数数・有限体表現・曲線関係式が固定的な部分を含むため、そのままBBGS対応済みとはみなさない。

## 7. 次に必要な確定事項

実装を誤らずに進めるため、対象とするBBGS塔の定義式（論文・式番号でも可）、段数、および基礎有限体を確定する。その情報をもとに関数体の標準形・場所の付値・有理点の列挙方法を固定してから、コードと実験記事を追加する。
